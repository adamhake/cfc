# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Chimborazo Park Conservancy website — a monorepo for a 501(c)(3) non-profit dedicated to preserving and enhancing Chimborazo Park in Richmond, VA's Church Hill neighborhood.

## Package Manager

**pnpm only** — `preinstall` blocks npm and yarn. Workspace dependencies use the `workspace:*` protocol.

## Conventions

- Biome uses `semicolons: asNeeded` — do not add trailing semicolons.
- Components PascalCase, hooks camelCase with a `use` prefix, route filenames mirror URL segments.
- Prefer named exports. Import via `@/` (app internals) or `@chimborazo/sanity-config` (shared schemas), not deep relative paths.
- Colocate tests as `*.test.ts(x)` next to the code they cover. Caching behavior is not unit-testable — follow the deploy-preview checklist in `apps/next-web/CACHING.md` when changing how data is fetched or invalidated.

## Shared Sanity Config (packages/sanity-config)

Shared Sanity schemas, GROQ queries, and client config used by next-web and studio. See `packages/sanity-config/CLAUDE.md` for conventions.

### Sanity Types (generated)

`packages/sanity-config/src/sanity.types.ts` is generated by Sanity TypeGen — never edit it by hand. After changing any schema or GROQ query, run:

```bash
pnpm --filter @chimborazo/sanity-config schema:generate
```

## Key Patterns

### Styling

- Tailwind CSS v4 with semantic color names (e.g., `text-green-800`, `bg-grey-50`)
- Dark mode via `dark:` prefix
- Custom fonts via `font-display` and `font-body` utilities

### Images

- Sanity CMS for managed media assets (preferred)
- Static images in `apps/next-web/public/`
- WebP format preferred for photos

## Deployment

- **next-web**: Netlify — `pnpm run build --filter=@chimborazo/next-web`
- **studio**: Sanity hosting — `pnpm --filter @chimborazo/studio deploy`

### Netlify Build Skipping

Each app's `netlify.toml` gates its build through `scripts/netlify-ignore.sh`, which skips a build when nothing under the app directory or the shared paths changed. It deliberately fails open — a needless build is cheap, a silently skipped deploy is invisible until someone notices the site is stale.

**When adding a workspace that other apps depend on, add it to `shared_paths` in that script** or dependent sites will stop rebuilding when it changes.

## Commits & PRs

Short, imperative, lower-case summaries describing the user-visible outcome ("add the park gallery to homepage"). Keep dependency bumps separate from feature work.

PRs: link the issue, note which app(s) are touched, include UI screenshots when relevant, call out new env vars, and confirm lint, test, and type-check pass.
